# Кладбище стратегий

**Честные проверки розничных «краёв» на крипто-перпах и фьючерсах MOEX — и инфраструктура, которая их произвела.**

English: [README.md](README.md) · Журнал исследования: [docs/FINDINGS.md](docs/FINDINGS.md), [docs/REVIEW.md](docs/REVIEW.md) · Разборы: [posts/](posts/) · Telegram: [t.me/strategy_graveyard](https://t.me/strategy_graveyard)

Это четырёхмесячный самостоятельный исследовательский проект (июнь–сентябрь 2026). Он начинался как поиск торгового края в микроструктуре рынка и в лид-лаге между инструментами, а закончился вещью более редкой: набором *отрицательных результатов, которым можно верить*. Каждая идея из таблицы ниже реализована, прогнана через event study, walk-forward с реальными издержками и проверку на концентрацию — и закрыта числом, а не мнением.

Итог одной строкой: **на минутном горизонте на ликвидных инструментах отношение края к издержкам равно 0.4–0.8 — на четырёх инструментах, двух площадках, двух режимах рынка и четырёх разных «проводниках».** Единственный раз, когда край оказался выше издержек, — паника марта 2020, где дневные ходы были 5%+. Это свойство режима, а не сигнала.

## Методология — почему отрицательным результатам можно верить

Большинство розничных бэктестов положительны из-за метода, а не из-за рынка. Правила, благодаря которым эти результаты держатся:

1. **Event study раньше любого бэктеста.** Условная доходность в bp в сторону гипотезы через 1/2/5/15/60 минут после события; события прорежены до одного на горизонт; разрезы hot/calm и по часам; сравнение с тиком + комиссией + полуспредом. Гипотеза жива, только если эффект ≥ 3–5 издержек, t ≥ 3 после прореживания и знак тот же минимум в двух периодах из трёх.
2. **Walk-forward с непересекающимися тестовыми окнами** и долей прибыльных окон. Одно окно врёт («BTC maker +2%, Sharpe 9» на пяти окнах стал −4%).
3. **Раскладка каждой зелёной клетки на концентрацию**: доля топ-5 дней, лонг против шорта, по часам. Край, который сидит в трёх днях или в одной стороне ралли, — это экспозиция, а не край.
4. **Контроль «собственный импульс»**: тот же тест проводника с лидером = сама цель.
5. **Инверсия сигналов как диагностика**: если переворот направления не меняет P&L, убыток — издержки плюс шум, и переворачивать нечего.
6. **Издержки за сторону**: тик, комиссия, полуспред; мейкер-модель с adverse selection (лимитка исполняется, только если цена реально дошла до неё, — прибыльные «убежавшие» сделки теряются).
7. **Без заглядывания вперёд**: сигнал бара *i* исполняется по Open бара *i+1*; реактивные фильтры, ранжирование по будущему результату и исполнение по Close сигнального бара названы поимённо и исключены.
8. **Правила объявлены заранее; чувствительность ≠ подбор.** Свипы параметров печатаются как таблицы чувствительности и никогда не используются для выбора заголовочной цифры.
9. **t-статистика, а не годовой Sharpe на коротких отрезках**: Sharpe 1.48 на 66 днях — это t = 0.63.
10. **Фильтр стыка сессий** для инструментов с перерывом в торгах (первый бар сессии FORTS содержит весь ночной ход лидера; половина «событий в час открытия» оказалась фантомами).

Подробности и разобранные примеры: [docs/FINDINGS.md § 5](docs/FINDINGS.md), [docs/REVIEW.md § 3 и § 5](docs/REVIEW.md).

## Инфраструктура

Всё ниже работает без присмотра на одном небольшом VPS (Docker Compose) и копит данные с июня 2026.

| Компонент | Что делает |
|---|---|
| [`collector/collector.py`](collector/collector.py) | Websocket Binance USDT-M futures → ClickHouse: снимки depth20 (1 с), агрегированные сделки, mark price + фандинг (1 с), принудительные ликвидации (`forceOrder`), открытый интерес (REST-опрос). Батч-вставка, авто-реконнект, `restart: unless-stopped`. |
| [`collector/index_collector.py`](collector/index_collector.py) | Котировки US-индексов «с крипты»: токенизированные SPY/QQQ (xStocks) на Kraken (ws v2, триггер `bbo` — по умолчанию `trades` даёт одно обновление в 8 минут) и Gate (ws v4 `book_ticker`), Yahoo как эталон best-effort, Pyth Hermes опционально. Измеренная задержка ленты Gate: 113–116 мс. |
| [`collector/*.sh`](collector/) | Серверные проверки: строки по символам и свежесть лент, дневная волатильность, каскады ликвидаций, рост диска и «на сколько суток хватит». |
| [`export_moex.sh`](export_moex.sh), [`export_conductors.sh`](export_conductors.sh) | SQL для ClickHouse над архивом FORTS 2018–2020 (стакан QUIK, сделки): минутные бары с признаками плит и дисбаланса, объёмом агрессоров-покупателей/продавцов, касаниями, внутриминутной волатильностью, последним снимком стакана. |
| [`fetch_moex_iss.py`](fetch_moex_iss.py), [`fetch_daily.py`](fetch_daily.py), [`fetch_dukascopy.sh`](fetch_dukascopy.sh), [`fetch_us_index.sh`](fetch_us_index.sh) | Загрузчики бесплатных данных с ретраями и докачкой: минутные и дневные свечи MOEX ISS по контрактам с непрерывным фронтом по объёму (и задокументированной коллизией кодов SECID), дневки Binance/Bybit + история фандинга, минутки Dukascopy. |
| [`trading_analyzer/`](trading_analyzer/) | Движок бэктеста без lookahead, риск-модуль (фиксированные/ATR-стопы, трейлинг, fixed-fractional сайзинг), мейкер-модель с adverse selection, walk-forward, портфельный walk-forward, ансамбль детекторов с режимными воротами, экспорт в SQL для Grafana. |
| [`event_study.py`](event_study.py), [`conductor_check.py`](conductor_check.py), [`lead_triage.py`](lead_triage.py), [`tail_test.py`](tail_test.py), [`sp_ri_strategy.py`](sp_ri_strategy.py) | Исследовательский слой: event study с прореживанием, триаж лид-лага (β, корреляции на лагах, многофакторная регрессия), тест множителя хвостовых дней, структура сделки с издержками и фильтром сессий. |
| [`trend_daily.py`](trend_daily.py), [`funding_scan.py`](funding_scan.py) | Дневной горизонт: заранее объявленное трендовое правило с фандингом, допуском по ликвидности и лонгом в споте; сканер эпизодов экстремального фандинга с симуляцией ограниченного капитала. |
| [`grafana/`](grafana/) | Провижининг дашбордов: плиты в стакане, цена, дисбаланс. |

Стек: Python 3.9, только pandas/numpy (без тяжёлых зависимостей), ClickHouse, Docker Compose, Grafana.

## Воспроизвести результаты на открытых данных (ключи не нужны)

```bash
pip install -r requirements.txt

# Скан экстремального фандинга по всем USDT-перпам Binance (≈ 20 минут загрузки, потом секунды)
python funding_scan.py --fetch --scan --confirm 3

# Трендовое правило на дневках перпов Binance с фандингом (≈ 5 минут загрузки)
python fetch_daily.py --binance && python trend_daily.py --source crypto --exchange binance
python trend_daily.py --source crypto --exchange binance --top 4 --long-spot

# То же правило на фьючерсах MOEX как вневыборочный контроль (MOEX ISS, бесплатно)
python fetch_daily.py --moex && python trend_daily.py --source moex
```

Коллектору нужен сервер с Docker: `cd collector && docker compose up -d` (задать `CLICKHOUSE_PASSWORD`; символы — `SYMBOLS` в `docker-compose.yml`). Скрипты деплоя берут `COLLECTOR_HOST` и `COLLECTOR_KEY` из окружения. Runbook: [docs/RUNBOOK.md](docs/RUNBOOK.md).
